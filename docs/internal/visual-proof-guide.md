# Visual proof guide — screenshots & demo video

How to capture the execution evidence each workflow README references.
Owner-assisted: the owner runs the captures in their n8n instance; nothing
here is generated by an agent.

## Redaction rules (apply to every capture)

Before saving any screenshot, check it contains **none** of:

- Account IDs, project IDs, spreadsheet IDs, ad account IDs
- Real client names, real email addresses, real chat IDs
- The n8n instance URL (browser address bar — crop it out)
- API keys or tokens visible in credential pickers
- The n8n instance identifier (64-char hex) anywhere

When in doubt, blur the cell or retake the shot on demo data.

## Shot list per workflow

### affiliate-intake

1. **Test run, whole canvas** — execute "When clicking 'Test workflow'",
   capture the run panel showing 6 items in, the `Qualified?` branch
   splitting, and the single `Owner digest` output.
2. **Annotate:** the merge into one digest; the reject reason codes.
3. Frame: one image, canvas + execution panel side by side.

### daily-cash-tally

1. **Demo run** — test run showing the five route outcomes
   (clean / alert / escalation / quarantine / digest) all visited.
2. **Quarantine tab** — screenshot the `Park row in quarantine` output
   item (demo data only).
3. **Annotate:** the 30-day history read; the escalation threshold.

### faq-chatbot

1. **Chat demo** — the embedded chat window answering a seeded FAQ hit.
2. **Approval queue** — the `FAQ-Pending` sheet tab with a drafted entry
   waiting for owner approval (this is the differentiator — show it).
3. **Weekly digest output** — `Owner weekly digest` item.

### promise-ledger

1. **Chase approval queue** — `Chase-Queue` sheet tab holding a drafted
   chase email (again, the HITL seam is the selling point).
2. **Fulfillment close** — a run where `Row matched?` → `Mark done in
   ledger` flips a promise to done.
3. **Digest suppression** — a run where `Digest worth sending?` sends
   nothing (quiet-by-design).

### client-report-generator

1. **Full run** — one test run through the demo config (4 clients,
   `live:false`): the per-source fetch branches, normalize, compose.
2. **Draft-review seam** — the Gmail **draft** the demo produces
   (`delivery_mode=draft`), not a sent email.
3. **Ledger idempotency** — re-run and show `Already sent?` suppressing
   the duplicate.
4. **Error lane** — the `On workflow error` lane, with a note in the
   caption that it arms via Settings → Error workflow.

## Loom script — client-report-generator (2–3 min)

Record at 1080p, browser zoomed so the canvas fills the frame. Speak
slowly; each numbered block ≈ 20–30s.

1. **Hook (0:00–0:20)** — "This is a workflow that produces a branded
   weekly report for every client in a spreadsheet — data pulled from
   Meta Ads, Google Ads and GA4, deltas computed deterministically, and a
   human review step before anything is sent."
2. **Import (0:20–0:40)** — import `workflow.json` fresh; point out it
   runs the demo with zero credentials.
3. **Test run (0:40–1:20)** — press Test workflow; let the viewer see all
   branches light up; hover the `Normalize` and `Dedupe check` nodes.
4. **Config sheet (1:20–1:50)** — show the `config` tab: "adding a client
   is one spreadsheet row — sources, channels, brand colors, thresholds."
5. **Draft-review seam (1:50–2:20)** — open the generated Gmail draft;
   "`delivery_mode=draft` means a human approves every report until the
   client trusts it — then it's a flag flip."
6. **Reliability (2:20–2:45)** — point at the error lane and the
   idempotent ledger: "retry on every API call, one report per client per
   ISO week, per-source failures alert instead of crashing the batch."
7. **Close (2:45–3:00)** — "Same structure works for any multi-source
   reporting pipeline. Repo link in the description."

Keep the video public-unlisted until the owner approves publishing.
